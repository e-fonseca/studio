O que vai para o GitHub, e o que não vai

Vai o código do sistema: {{ quantos_arquivos }} arquivos de programa, tela e documentação. É um backup fora do servidor da loja, com histórico de cada versão.

O banco de dados não vai, e isso é de propósito. Nele estão os nomes dos clientes que vêm do SET, o extrato bancário e as notas fiscais anexadas aos pedidos. GitHub é um serviço fora da loja; esse dado continua no servidor, no backup que roda todo dia às 23:30 e guarda 14 dias em C:\cabana-sistema\backups.

Senha nenhuma vai. O arquivo de configuração com a senha do e-mail e a chave do sistema fica fora da pasta do programa, e o envio monta a lista pelo que pode ir.

Como preparar, uma vez só

{% comment %}O repositório já vem preenchido desde a 1.32.0, então o primeiro passo não é mais criar um: é conferir. O token continua sendo dele, e é a única parte que o sistema não tem como preencher sozinho.{% endcomment %}
  1. Confira o repositório aqui embaixo: ele já vem preenchido. No GitHub, ele precisa existir e ser privado.
  2. Abra a página de gerar token (este link já vai direto nela) e gere um com acesso só a esse repositório e permissão Contents: Read and write. No prazo, quanto mais longo melhor: o sistema avisa antes de vencer.
  3. Cole o token aqui embaixo e grave. Acabou: gravar já liga o envio automático e já manda a primeira cópia, e o resultado aparece aqui em cima. Não há passo seguinte.

O token é a única parte que não dá para automatizar: o GitHub exige que uma pessoa dê a permissão, e é isso que impede um programa de escrever na conta de alguém sozinho. Tudo o que vinha depois dela o sistema faz.
